# WordPress / GAS 共通版の更新と対応状況

更新日: 2026-09-06。ローカル候補版: 0.6.131。

## 正本

正本は、このファイルがある `Voice-Casting-Studio` リポジトリです。
WordPress版とGAS版は `src/main.jsx`、`src/components`、`src/lib/recording.js` を共用します。
GASの声優向けURLも同じAppを表示します。以前の簡易声優画面を別途改修しないでください。

旧Claude作業フォルダーには `CLAUDE.md` / `AGENTS.md` で正本への案内を設置しました。
旧フォルダーのアプリ自体は上書きしていません。

「同じ画面」と「すべての外部連携まで同等」は別です。上表の未対応項目がある間は完全互換と表示しないでください。

## 共有と権限

- 共有プロトコルは `2`。サーバー側 `Code.gs` とフロントを一緒に更新する必要があります。
- GASに保存する共有用データは許可した項目だけです。オーナー用APIキー、応募者の個人情報、アクセスキー一覧、非公開タスクの設定などを声優向けレスポンスへ含めません。
- 本文から展開したセリフの担当者は、オーナーが公開した `recordingLineIndex` で検証します。声優側が送信する担当者情報を信用しません。
- 更新はロック下で保存します。一括更新は全件を検証してからファイルに書き込みます。
- 質問の削除は削除IDも共有して、古い公開内容による復活を防ぎます。
- フィールドごとの時刻による競合解決のため、端末時計の大きなずれには注意が必要です。

## 以後の更新

1. 正本の共通ソースを変更します。WordPress向けとGAS向けで同じ画面を複製しません。
2. 保存・外部APIに関わる変更は、`src/lib/workspace.js` の接続先と `docs/google-apps-script/Code.gs` の両方を確認します。
3. `npm run build:all` を実行します。全テスト、GASビルド、WordPressビルドを順に実行し、共通ソースの指紋を記録します。
4. GASフロントは `dist/`、WordPress候補は `artifacts/paired-build/wordpress/voice-casting-studio/`、GAS受信口は `artifacts/paired-build/gas-backend/Code.gs` に出力されます。
5. 各 `build-info.json` のバージョンと `sourceSha256` が一致することを確認します。
6. WordPressとGASフロントをそれぞれ公開します。GASサーバー変更を伴う場合はApps Scriptも新しいバージョンとして再デプロイします。
7. 制作者と声優2名のテストデータで、保存、再読込、担当者制限、リテイク、質問、素材再生を確認します。

GitHub ActionsのPagesワークフローも `build:all` を呼ぶよう変更しています。
公開の完了はGitHub Actionsの成功と公開先の `build-info.json` で確認します。
CIはApps Scriptの本番デプロイを自動では行いません。

公開URL、実行ユーザー、公開範囲、秘密トークンは維持しています。

既存作品には担当者検証用の索引だけを追加しました。303件の保存行、キャラクター、配役・共有キー、既存の進捗を、更新前後のDriveファイルで照合済みです。
実データ、共有キー、秘密トークンを含むバックアップと検証レポートは公開リポジトリの外に保存し、GitHubへ含めません。

## 既存GASの更新順序

1. Apps Script編集URL、現在のデプロイ、共有保存先を確認し、既存JSONを日時付きでバックアップします。
2. 既存の保存先ID、共有キー、秘密トークンを保持して受信口を更新します。秘密情報をGitへ記録しません。
3. テスト用保存先でプロトコル2の動作を確認します。
4. 本番受信口を再デプロイし、共通フロントも公開します。
5. オーナー画面の「配役・共有」から既存作品の共有内容を更新し、セリフの担当者索引を保存します。
6. 声優URLで最新版が見えることと、保存したチェックをオーナーが取得できることを確認します。

古い受信口に新しいフロントだけを接続すると、更新が必要である旨を表示します。
検証に成功していない状態を「共有済み」として扱わないでください。
